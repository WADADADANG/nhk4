### 1. 🔥 จุดที่ดึง CPU สูงผิดปกติ (CPU Bottlenecks)

#### 1.1 Tesseract OCR ใน Party Vision สแกนข้อความแบบบล็อกเธรด
- **ไฟล์ที่พบ:** [vision-service.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/vision-service.js#L400-L503) (`extractMemberNames`)
- **สาเหตุ:** หากเปิดใช้งานตัวเลือก `readNames: true` (อ่านชื่อสมาชิกปาร์ตี้) ในโหนด Party Scanner / Party Buff ตัวระบบจะนำภาพชื่อสมาชิกทุก Slot (สูงสุด 8 ช่อง) มาครอป ขยายความละเอียด 3 เท่า แปลงเป็นภาพขาวดำ แล้วสั่ง `worker.recognize(binImageBuffer)`
- **ผลกระทบ:** Tesseract.js ทำงานบน CPU 100% เต็มทุกคอร์ การรัน OCR ต่อเนื่องทุก ๆ 250ms จะทำให้ **CPU พุ่งแตะ 100% ทันที** ส่งผลให้ Bot Engine และหน้าต่างเกมเกิดอาการกระตุกค้าง (Freezing)
- **แนวทางแก้:** ปิด `readNames` เป็นค่าเริ่มต้น (ใช้การระบุสมาชิกด้วย Slot Index 1–8 แทน) หรือหากจำเป็นต้องใช้ ควรสแกนชื่อเฉพาะครั้งแรกที่จับตี้ได้ แล้ว Cache ไว้ถาวร ไม่ต้องอ่านซ้ำทุก Loop

#### 1.2 `emitSignal` + `sendRealtimeOverlayState` ทำงานถี่เกินไป (High-Frequency IPC Storm)
- **ไฟล์ที่พบ:** [bot.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/bot.js#L123-L138) และ [bot.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/bot.js#L346-L357)
- **สาเหตุ:** ทุกครั้งที่ Action ทำงาน, มีการวนลูป, หรือ Branch ตรวจเงื่อนไข ระบบจะเรียก `emitSignal()` ซึ่งข้างในจะเรียก `sendRealtimeOverlayState()` ทันที:
  ```javascript
  // bot.js
  console.log('__OVERLAY_DATA__' + JSON.stringify(payload));
  ```
  ใน [launcher/main.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/launcher/main.js#L516-L533) จะคอยดักจับ `stdout` ทุกบรรทัด แล้วทำการ `JSON.parse` จากนั้นยิง `webContents.send('overlay:update')` ไปยังหน้าต่าง Electron
- **ผลกระทบ:** หากผู้ใช้ตั้งค่าลูปการกดปุ่มความเร็วสูง (เช่น 50–100ms) สัญญาณจะถูกส่งออกมา 20–40 ครั้งต่อวินาที ทำให้เกิด **IPC Flooding**, CPU ของ Node.js และ Electron Main Process พุ่งสูง และ Terminal Buffer ล้น
- **แนวทางแก้:** เพิ่ม **Throttle / Debounce** ให้กับ `sendRealtimeOverlayState()` (เช่น ส่งอัปเดตสูงสุดไม่เกิน 4-5 ครั้งต่อวินาที หรือ 200–250ms ต่อครั้ง)

#### 1.3 ลูปตรวจจับการหลุดโฟกัสในหน้าเว็บรันทุก 50ms (`In-Page Defocus Sentinel`)
- **ไฟล์ที่พบ:** [bot.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/bot.js#L1594-L1598)
- **สาเหตุ:** โค้ดฉีดเข้าไปในเบราว์เซอร์ของทุกหน้าจอเกม:
  ```javascript
  setInterval(() => {
      if (!document.hasFocus() && (heldPhysicalKeys.size > 0 || heldPhysicalButtons.size > 0)) {
          releaseAllStuckPhysicalInputs();
      }
  }, 50);
  ```
- **ผลกระทบ:** ฟังก์ชันนี้จะตื่นขึ้นมารันบน Main Thread ของหน้าเว็บเกมทุก ๆ 50ms ในทุกจอ (เปิด 8 จอ = รัน 160 ครั้งต่อวินาที)
- **แนวทางแก้:** พึ่งพา Event-driven จาก `window.addEventListener('blur')`, `focusout`, และ `visibilitychange` เป็นหลัก และปรับ Sentinel Interval ให้ห่างขึ้นเป็น 250–500ms

### 2. 💾 จุดที่กิน RAM สูงและเสี่ยง Memory Leak (RAM & Memory Leaks)

#### 2.1 บัฟเฟอร์ Screencast Compositor ค้างในหน่วยความจำ
- **ไฟล์ที่พบ:** [vision-service.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/vision-service.js#L127-L135) (`ClientScreencastManager`)
- **สาเหตุ:** การดึงเฟรมจาก Chrome Compositor Stream (`Page.screencastFrame`) แปลง Base64 เป็น `Buffer.from(data, 'base64')` อย่างต่อเนื่อง หากรันหลายจอพร้อมกัน Garbage Collector (GC) ของ V8 จะต้องคอยเคลียร์ Buffer ก้อนใหญ่ตลอดเวลา
- **ผลกระทบ:** หาก GC ทำงานไม่ทัน จะเกิดอาการ RAM ค่อย ๆ บวมขึ้นเรื่อย ๆ (Memory Bloat) โดยเฉพาะเมื่อมีทั้ง 8 จอเปิด Screencast พร้อมกัน
- **แนวทางแก้:** ตรวจสอบว่าหน้าจอใดไม่ได้เปิดใช้งานฟังก์ชัน Party Vision ให้หยุด Stream ทันที (`stopStream`) และ Re-use Buffer หรือตั้ง Throttle เฟรมภาพ (`everyNthFrame`) ให้เหมาะสม

#### 2.2 อาร์เรย์สัญญาณสะสมในหน่วยความจำ
- **ไฟล์ที่พบ:** [bot.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/bot.js#L125-L134)
- **สาเหตุ:** `global.executionSignals` ถูก `push` ข้อมูลสัญญาณการทำงานเข้ามาเรื่อย ๆ ถึงแม้จะมีการตัดด้วย `.splice(0, length - 80)` แต่หากฝั่ง SSE (`test-server.js`) หรือ Web Canvas ไม่ได้เชื่อมต่อ ตัวแปรนี้จะค้างอยู่ใน Memory และถูกสร้าง Object ใหม่ตลอดเวลา

### 3. 🎮 จุดที่ดึง GPU สูงและทำให้หน้าจอกระตุก (GPU Spikes & Rendering Lag)

#### 3.1 Fallback Screenshot บังคับ GPU Readback (Zero-Flicker หลุด)
- **ไฟล์ที่พบ:** [vision-service.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/vision-service.js#L808-L827)
- **สาเหตุ:** ใน `scanClientPage` มีเงื่อนไข Watchdog:
  ```javascript
  const isStale = !session || !session.lastFrameTime || (now - session.lastFrameTime > 600);
  if (!frameBuffer || isStale) {
      frameBuffer = await page.screenshot({ type: 'jpeg', quality: 85 });
  }
  ```
- **ผลกระทบ:** หากตัวเกมในจอนั้นยืนอยู่นิ่ง ๆ (ไม่มีแอนิเมชันเคลื่อนไหวเกิน 600ms) Compositor จะไม่ส่งเฟรมใหม่ ทำให้เงื่อนไข `isStale` เป็นจริง ส่งผลให้ระบบสั่ง `page.screenshot()` ทันที ซึ่งคำสั่งนี้จะสั่ง GPU บังคับเรนเดอร์และดึงข้อมูลกลับ (GPU Readback) ทำให้หน้าจอเกมเกิดอาการกระตุกหรือกระพริบอย่างเห็นได้ชัด
- **แนวทางแก้:** ขยายเวลา Watchdog หรือใช้เฟรมล่าสุดที่มีอยู่แล้วหากเกมไม่มีการเปลี่ยนแปลง แทนที่จะบังคับสั่งถ่ายภาพหน้าจอใหม่

#### 3.2 Visual HUD Overlay วาด Canvas ทับหน้าจอเกมทุกรอบสแกน
- **ไฟล์ที่พบ:** [vision-service.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/vision-service.js#L1154-L1285) (`VisualOverlay.render`)
- **สาเหตุ:** การวาดกรอบสีเขียว/แดง/ข้อความ HP ทับลงบนหน้าจอเกมผ่าน `page.evaluate()` ทุก ๆ รอบการสแกน (250ms) บังคับให้เบราว์เซอร์ของเกมต้องเคลียร์และวาด Canvas 2D ซ้อนทับเลเยอร์ WebGL 3D ตลอดเวลา
- **ผลกระทบ:** WebGL Renderer ต้องประสานงานกับ 2D Canvas ทำให้ GPU ต้องสลับ Context และกินพลังงาน GPU สูงขึ้น
- **แนวทางแก้:** ปิด Visual Overlay (`showOverlay: false`) ในโปรไฟล์ที่ต้องการประสิทธิภาพสูงสุด หรือให้วาดเฉพาะตอนที่ผู้ใช้เปิดดูหน้าจอเท่านั้น

#### 3.3 Web Studio Canvas: ลบและสร้าง SVG ใหม่ทั้งก้อน (`innerHTML = svgContent`)
- **ไฟล์ที่พบ:** [public/js/canvas.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/public/js/canvas.js#L2246) (`renderWires`)
- **สาเหตุ:** ทุกครั้งที่มีการลากโหนด, เลื่อนหน้าจอ (Pan), หรือมีเส้นสายไฟขยับ ฟังก์ชัน `renderWires()` จะใช้คำสั่ง:
  ```javascript
  this.svgLayer.innerHTML = svgContent;
  ```
- **ผลกระทบ:** เบราว์เซอร์ต้องทำลาย DOM Nodes ของสายไฟและตัวกรอง Glow (`<feGaussianBlur>`) ทั้งหมด แล้ว Parse ข้อความ HTML ประกอบใหม่ บังคับให้เกิด Layout Thrashing และ GPU Repaint ทำให้ตอนที่มีโหนดเยอะ ๆ (20+ โหนด) การลากหน้าจอจะหน่วงและกระตุกมาก
- **แนวทางแก้:** ใช้การอัปเดตเฉพาะแอตทริบิวต์ `d` ของ `<path>` ที่มีอยู่เดิม แทนการเขียนทับ `innerHTML` ทั้ง Layer

### 4. 💽 ปัญหา Disk I/O และการอ่านไฟล์ซ้ำซ้อน (Disk Thrashing)

#### 4.1 `readConfig()` อ่านไฟล์ JSON ทุกไฟล์บนดิสก์ซ้ำ ๆ ทุก 1–2 วินาที
- **ไฟล์ที่พบ:** [config-store.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/config-store.js#L169-L274)
- **สาเหตุ:**
  1. `launcher/main.js` มี Health Check ตรวจสอบบอททุก 1–3 วินาที (`checkBotHealth` -> เรียก `/api/config`)
  2. `launcher/ui/launcher.js` ยิงเรียก `/api/status` และ `/api/config` ทุก 2 วินาที (`syncBackendStatus`)
  3. `public/js/app.js` ยิง Polling ทุก 3 วินาที (`pollActiveClients`)
  - **ในฟังก์ชัน `readConfig()`:** ทุกครั้งที่มี Request เข้ามา มันจะเรียก `fs.readdirSync(PROFILES_DIR)` แล้วใช้ `fs.readFileSync` วนลูปอ่านไฟล์โปรไฟล์ `.json` **ทุกไฟล์ในเครื่องแบบ Synchronous** พร้อมรันตัวแปลง Normalize ทุกรอบ!
- **ผลกระทบ:** ดิสก์ต้องอ่านไฟล์ JSON นับสิบไฟล์ต่อเนื่องตลอด 24 ชม. ส่งผลให้เกิด Micro-Stutter บน Windows และเปลือง CPU โดยใช่เหตุ
- **แนวทางแก้:** ทำ **In-Memory Cache** สำหรับ Config เมื่ออ่านครั้งแรกแล้วให้จำไว้ในตัวแปร และจะอ่านไฟล์ใหม่อีกครั้งก็ต่อเมื่อ File Watcher ตรวจพบว่าไฟล์มีการเปลี่ยนแปลงจริง ๆ เท่านั้น

#### 4.2 การบันทึก Log ลงดิสก์แบบบล็อกเธรด (`appendFileSync`)
- **ไฟล์ที่พบ:** [launcher/log-manager.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/launcher/log-manager.js#L72)
- **สาเหตุ:** ทุกข้อความที่บอทพิมพ์ออก Console จะถูกนำมาเขียนลงไฟล์ Log ด้วย `fs.appendFileSync()` ทันที
- **ผลกระทบ:** ในจังหวะที่บอทพิมพ์ Log ถี่ ๆ การใช้ Synchronous I/O จะบล็อก Event Loop ของหน้าต่าง Launcher ชั่วคราว ทำให้หน้าต่าง Launcher ค้างคลิกไม่ติด
- **แนวทางแก้:** เปลี่ยนมาใช้ `fs.createWriteStream` หรือบัฟเฟอร์ข้อความไว้แล้วเขียนเป็น Batch

### 5. 🌐 ปัญหาการเปิดหลายจอ (Multi-Client Scalability: 1–8 จอ)

#### 5.1 RAM สะสมตามจำนวนจอของ Chromium
- **ไฟล์ที่พบ:** [bot.js](file:///c:/Users/WADADADANG/Desktop/MyProjects/NodeHotkey/bot.js#L1662-L1716) (`launchBrowser`)
- **รายละเอียด:** ปัจจุบันมีการใส่ Flag ลดการใช้ RAM เช่น `--disable-extensions`, `--renderer-process-limit=1`, และจำกัด Cache ไว้แล้ว แต่ธรรมชาติของหน้าเว็บเกม WebGL 1 จอจะใช้ RAM ประมาณ **400MB – 800MB**

  - เปิด 8 จอ = ใช้ RAM ประมาณ 5.0 GB – 7.0 GB
- **จุดที่ต้องระวัง:** หากใช้เบราว์เซอร์ **Firefox** ตัวสคริปต์ได้ตั้ง `dom.ipc.processCount: 1` และ `javascript.options.mem.max: 512` ไว้ ซึ่งช่วยประหยัด RAM ได้ดีกว่า Chrome แต่ถ้าผู้ใช้เลือกใช้ Chrome/Edge จะไม่มีการจำกัด V8 Heap ในระดับ Process ส่งผลให้ RAM พุ่งสูงได้ง่ายกว่า
